# 山海契 · Unity 数值层交付包

把主方案（`../《山海契》玩法设计方案.md`）里**所有会被反复重算的数字**做成了一份可编译、可复算、
可在命令行验的 C# 代码，加上 Unity 侧的落地清单。**这里没有一行是游戏逻辑**——只有公式、数据、
和一张「谁该在 Update 里跑什么」的说明书。

---

## 三步上手

### 第 1 步：先证明数字是对的（不需要装 Unity）

```bash
cd Verify
dotnet run
```

最后一行必须是 `PASS`（当前：**178 条断言全绿**）。失败会打印 `FAIL` 并逐条给差异，退出码 1。

### 第 2 步：把 Stats 拖进 Unity

1. 新建或打开 Unity **2021.3 LTS** 工程（.NET Standard 2.1）。
2. 把本目录下的 `Stats/` 与 `UnityAssets/` 两个文件夹**整个**拖进工程的 `Assets/` 下
   （保持相对位置，两个 `.asmdef` 会一起过去）。
3. 等编译完成。`Stats` 程序集的 `noEngineReferences = true` 意味着它**编译期就拿不到 UnityEngine**，
   所以任何人不小心写了 `using UnityEngine;` 都会立刻报错——这条约束不是我写注释保证的，是编译器保证的。
4. 右键 `Assets/Stats/Data/Weapons.json` → 无菜单项也不要紧：新建
   `Create → 山海契 → 兵器表`，把 JSON 拖进脚本字段，执行 `ImportFromJson`（或直接在代码里调）。

### 第 3 步：按对照表搭场景

`设计到实现对照表.md` 从场景/预制体划分一路写到 F1 调数面板该显示哪 8 个字段。
先照 §1 建三个场景与 `P_Player`，再照 §6 挂状态机，剩下的按表填。

## 为什么 JSON 与 C# 类并存，而不是只有一份

- `Stats/Data/*.json` 是**数值的唯一来源**：Verifier 读它，Unity 的 SO 导入也读它。
- `Stats/Data/*Def.cs` 是**结构定义**（`[Serializable]` 公开字段），`JsonUtility` 与
  `System.Text.Json` 都能直接反序列化，两边不需要写两份映射。
- 根对象包了一层（`{"Weapons":[...]}`）是 `JsonUtility` 不支持根数组导致的，不是风格选择。

**这套断言是真的在测数据**（两种破坏性改法都实测过）：

- 把「锏」的耐久 265 改成 150（造成真正的四轴失衡）→ 立刻报 **2 对支配**（棒→锏 触及轴、鞭→锏 持续轴）并 FAIL；改回恢复 0 对。
- 把「棍」的横扫角 130 改成 60 → **仍然 0 对**：支配要求「四轴全不劣」，把一件兵器改弱只会更弱，不可能凭空造出支配者。这条恰好说明判定不是「随便变个数就报警」——要造出支配对必须让某件兵器在四轴上全面压过另一件。

## 数值来源纪律

- 所有数字来自主方案表格与公式，逐条照抄；**没有一处自行发明**。
- 主方案没给的（射器初速 55/65/45/40 m/s 标 `[估算]`、角弓满蓄单发 60 点标 `[估算]`），
  照抄并保留 `[估算]` 注释。
- 第 1 轮交付曾指出「§6.3 的控制轴需要横扫角，但 §6.2 表里没有这一列」——主方案已返工：
  §6.2 新增「横扫角（度）[估算]」列、§6.2b 给出六档依据，本工程改为**照抄**，不再自拟。
  同一轮还改掉了旧口径「长度 × 横扫角」的乘积算法（它会把 2.8 m 长槊判给 0.9 m 短刀），
  改为**四轴独立**：输出 DPS / 触及长度 / 横扫角 / 耐久。旧口径在本工程里只留作对照打印。
- **主方案一处未改。** 三轮发现的不自洽共 12 条，全部列在 `设计到实现对照表.md §9`：
  **12 条全部已被定稿吸收（0 条开着）**。最后一轮的两条：§6.3 的「33 对」经确认是转写错误
  （脚本一直打印 32），现文档写 32 且本工程六行对照 7 / 32 / 27 / 8 / 1 / 0 全部升级为硬断言；
  §11.5 的 Shift 同键冲突改为「翻滚 → 空格、换符 → Q、Shift 降为纯修饰预留」。

## 常见坑（先看这条省半小时）

**`dotnet run` 第一次会报 `Access to the path 'C:\Users\<you>\.dotnet\...sentinel' is denied`。**
这是沙箱/权限环境不允许写用户目录导致的，与工程无关。设一个可写目录即可：

```powershell
$env:DOTNET_CLI_HOME = "<可写目录>"; cd Verify; dotnet run
```

在正常开发机上直接 `cd Verify && dotnet run` 就行。
