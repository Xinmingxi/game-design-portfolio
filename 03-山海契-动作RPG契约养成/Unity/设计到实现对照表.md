# 《山海契》设计到实现对照表（Unity 落地清单）

> 上游权威：`../《山海契》玩法设计方案.md`（下称「主方案」）。本表只做**翻译**，不改数值。
> 代码侧唯一权威：`Stats/`（零 UnityEngine 依赖，可由 `Verify/` 在命令行复核）。

## 0. 一页速览

| 层 | 目录 | 是否碰 UnityEngine | 谁调用 |
| --- | --- | --- | --- |
| 纯数值 | `Stats/*.cs` | **否**（asmdef 里 `noEngineReferences: true` 编译期强制） | 任何层 |
| 纯数据 | `Stats/Data/*.cs` + `*.json` | 否 | 数值层 / Unity 资产层 |
| Unity 外壳 | `UnityAssets/DataAssets.cs` | 是（ScriptableObject） | Inspector / 运行时读表 |
| 验证 | `Verify/` | 否（net10 控制台） | CI / 本地 `dotnet run` |

**一句话分工**：`Stats/` 里只允许出现「输入 → 数字」的纯函数；一切 `Update`、插值、动画、
输入、物理都在场景脚本里，场景脚本只做两件事——**采样输入**、**把结果喂给 Stats**。

## 1. 场景与预制体划分

三个场景，按「一次外出的三段」切：

| 场景 | 承载 | 内含 | 离开条件 |
| --- | --- | --- | --- |
| `S_Camp` 营地 | 结算、养成、备装 | 灶台 / 兽栏 / 药圃 / 兵器架 / 存档点 / 信赖结算台 | 点「出发」→ 载入 `S_Zone_Qingqiu` |
| `S_Zone_Qingqiu` 青丘之野 | 切片主战场 | 4 个节点（每个节点一个 `NodeAnchor`）+ 采集点 + 妖巢 + 天气 | 撤退 / 被击倒 → 回 `S_Camp` |
| `S_Boot` 启动 | 读表 + 校验 | `DataBootstrap`（加载 JSON/资产、跑一次 `WeaponBudget.Check`、失败即红字） | 立刻转 `S_Camp` |

**为什么单独要 `S_Boot`**：§6.3 的反支配自检是「CI 用」的硬验收，把它放进 `S_Boot` 的
`Awake`，任何一次改表都会在进游戏前炸出来，而不是等玩家发现某件兵器没人用。

预制体清单：

| 预制体 | 根组件 | 子节点挂点 | 备注 |
| --- | --- | --- | --- |
| `P_Player` | `CharacterController` + `PlayerBrain` | `Socket_Weapon`（右手）、`Socket_Back`（收刀后背挂点）、`Socket_Torch`、`CamTarget` | 收刀/持械 = 兵器在 `Socket_Back` 与 `Socket_Weapon` 之间换父级，**不要**用动画事件驱动状态 |
| `P_Yao_<种>` ×14 | `NavMeshAgent` + `YaoBrain` | `Mouth`（投喂点）、`Ear_L/R`、`Tail`（W1 姿态三档）、`HitBox`、`FeedPoint` | 每只妖一个预制体；`YaoDef` 用 ScriptableObject 引用，不写死在预制体里 |
| `P_Ranged_Bow` / `_Crossbow` / `_Repeater` / `_Sling` | `RangedWeapon` | `Muzzle`（出射点）、`Sight_L/C/R`（三点准星） | 弹药是消耗品，走 `Inventory` |
| `P_Projectile` | `Projectile`（**无 Rigidbody**） | 拖尾 `TrailRenderer` | 解析式弹道，见 §5 |
| `P_Node` | `NodeAnchor` | 采集点、妖刷新点、立契判定球 | 4 个实例 = 切片全部内容 |
| `P_Interactable_*` | `IInteractable` 实现 | — | 投喂、包扎、剥皮、拾取共用一套交互提示 |

## 2. 脚本职责表（谁的 Update 里跑什么）

**铁律：`Update` 里不许出现公式。** 公式只在 `Stats/`，`Update` 只允许「取数 → 调 Stats → 用结果」。

| 脚本 | 所在场景对象 | Update 里做什么 | 明确不做 |
| --- | --- | --- | --- |
| `PlayerBrain` | `P_Player` | 读输入 → 写 `MoveInput`/`AttackPressed`/`SheatheToggled`；调 `PlayerStateMachine.Tick` | 不算伤害、不算 R |
| `PlayerStateMachine` | `P_Player` | 状态迁移（§6 的表）；管理 `Animator` 参数 | 不查表、不算概率 |
| `CombatProbe` | `P_Player` | `Physics.OverlapSphere` 取命中体 → 交给 `DamageResolver` | 不做数值计算 |
| `RangedWeapon` | 射器预制体 | 蓄力计时、准星张开（用 `Ballistics.Drop/Lead`）、发射时把参数抛给 `Projectile` | 不自己积分重力 |
| `Projectile` | `P_Projectile` | **每帧只算位置**：`pos = origin + dir * (v*t) + Vector3.down * Ballistics.Drop(v*t, v)` | 不读刚体速度、不做碰撞反弹 |
| `YaoBrain` | 妖预制体 | 感知、`NavMeshAgent` 追击、按 `Trust` 段位决定抗命/绕后/护主（W1/W2） | 不算信赖增减（交 `TrustDirector`） |
| `YaoStatus` | 妖预制体 | 血量、状态（怒/常/疲）、惊扰值缓存 | 不算 CPT |
| `TrustDirector` | `S_Zone` 常驻 | 订阅事件（投喂/协同击杀/误伤）→ `Trust.ApplyEvent`；日结算 `Trust.SettleDay` | 不碰动画 |
| `ContractDirector` | `S_Zone` 常驻 | 立契流程：查 `VolGates` → 算 `PVol/PForce` → 掷骰 → 调 `Backlash.JudgeSigning` | 不做 UI 布局 |
| `BacklashPresenter` | `S_Zone` 常驻 | 把 `BacklashResult` 翻译成表现（倒地、抢走消耗品、留创 Debuff） | 不重新判定 |
| `AgitationSystem` | `S_Zone` 常驻 | 每 1 s tick：`Contract.UpdateAgitation` | 不判定门槛 |
| `DayCycle` | `S_Camp` | 每日结算（衰减、记仇期、丹毒清除） | 不做场景加载 |
| `DebugPanel`(F1) | `P_Player` | 只读显示 8 个字段（§7） | 不写业务状态 |
| `DataBootstrap` | `S_Boot` | 读表、跑 `WeaponBudget.Check`、断言 18/14/16 | 不参与玩法 |

依赖方向（asmdef 已固定）：
`Scene/UI → ShanHaiQi.UnityAssets → ShanHaiQi.Stats`，反向引用编译期就会报错。

## 3. 输入映射（键位照主方案 §11.5 键位表，两套实现）

> 主方案返工后**已有权威键位表 §11.5**，本节目的是同一张表在两套 Input 方案下的落地写法，
> 不再由本文件自拟键位。两条不可动的设计意图（§11.5）：右键是**状态开关**不是攻击；
> 妖指令**松手才执行**（Trust &lt; 40 时命令延迟 +0.4 s，把关系做成输入延迟）。

### 3.1 旧 Input Manager（Unity 2021 默认，零依赖，原型首选）

`Project Settings → Input Manager` 建以下条目：

| 操作（§11.5 原文） | 键位 | Action / 轴名 | 触发的机制 |
| --- | --- | --- | --- |
| 移动 / 视角 | W A S D / 鼠标 | `Horizontal` `Vertical` / `Mouse X` `Mouse Y` | 位移；6 m 内奔跑 → 惊扰 +10 |
| **攻击 / 放箭** | 鼠标左键 | `Fire1` | 持械 = 攻击；持弓弩 = 按住蓄力、松开放箭（§7.2） |
| **收刀 ⇄ 持械** | 鼠标右键 | `Fire2` | **状态开关**：改 `Q_gear`（1 ⇄ 0）与 `AgitationEvent.RaisedWeapon`（+25） |
| 交互 / 投喂 / 立契 | E | `Interact` | 投喂、包扎、采集；**长按 0.8 s** 才进立契界面（防误触） |
| 翻滚 / 闪避 | **空格** | `Roll` | 耗体力；负重 &gt; 70% 距离 −20%。**单键无修饰**：战斗反射动作不能等修饰键 |
| 符箓 | **F**（**Q = 换符种**） | `Talisman` / `TalismanCycle` | F 用当前符；Q 切换符箓种类（§11.5 定稿：原「Shift+F 换符」已取消） |
| （预留）修饰键 | **Shift** | — | **当前不绑定任何动作**，只作修饰键预留（正式版若加「疾跑」直接用它，不必改其它键） |
| 阵法 | G | `Formation` | 布设 2.5 s，移动即打断（§8.3） |
| 丹药 | R | `Pill` | 服食 1.2 s，受击打断（§8.4） |
| 切换兵器 | 1 / 2 | `Swap1` `Swap2` | 切片只有刀 / 枪 |
| 妖指令 | Tab **按住 ≥ 0.3 s** | `YaoCommand` | 轮盘在按住满 0.3 s 后才出现；松手执行：左右 = 跟随/绕后，上 = 攻击锁定，下 = 退回 |
| 妖列表 / 图鉴 | Tab **点按 &lt; 0.25 s** | `YaoList` | 看 3 个契约位的 Trust 与段位（§5.3）；点按绝不弹出指令轮盘 |
| 暂停 / 设置 | Esc | — | 不可改 |
| 调试面板 | F1 | `Debug` | **仅开发构建**（§11.5），正式包不编译 |

**同键多身份的唯一判定标准（§11.5 定稿原文）**：一个键可以因为**手上拿着什么 / 面前是什么**
承担不同语义（上下文切换），但**不能因为「按多久」或「加哪个修饰键」而承担两个战斗中同时要抢的语义**。
按这条标准清表的结果，也是本文件第一轮提过的那个冲突的最终处置：

| 疑似冲突 | 判定 | 处置 |
| --- | --- | --- |
| 左键 = 攻击 / 蓄力放箭 | 不算冲突（由手上拿什么决定，互斥） | 保留 |
| E = 交互 / 投喂 / 立契 | 不算冲突（由面前是什么决定） | 保留，立契另加长按 0.8 s 防误触 |
| Shift = 翻滚 + Shift+F 换符 | **算冲突**（翻滚是战斗反射，Shift 当修饰键会被误触） | **已改**：翻滚 → 空格、换符种 → Q、Shift 降为纯修饰预留 |
| Tab = 点按列表 / 按住指令 | 不算冲突但需阈值（无修饰键） | 保留，阈值写死 **点按 &lt;0.25 s / 按住 ≥0.3 s** |

> 实现提醒：两套 Input 都要把 Tab 的两个语义做成**互斥的交互处理器**（新 Input System 用
> `TapInteraction(0.25)` 与 `HoldInteraction(0.3)`），不要用同一回调里 if/else 判 `isPressed` 时长，
> 否则松手瞬间两个语义会同时触发。

**「奔跑」暂不占键**：§11.5 只把 Shift 留作修饰键预留（「正式版若加疾跑直接用它」），而 §4.5 的
「在它 6 m 内奔跑 +10」需要奔跑态。实现约定：连续全速移动 1.5 s 进入「奔跑态」，由 `AgitationSystem`
每 6 m 半径记一次 +10；将来接 Shift=疾跑时，这行逻辑不改，只是触发阈值换成按键。

```csharp
// PlayerBrain.Update 的全部内容量级——只有采样，没有公式
float mx = Input.GetAxisRaw("Horizontal");
float my = Input.GetAxisRaw("Vertical");
if (Input.GetButtonDown("Fire2")) _sm.Request(StateEvent.SheatheToggle);
if (Input.GetButtonDown("Interact")) _interactor.TryInteract();
```

## 4. 物理层与碰撞矩阵

层（`Tag & Layers`）—— 严格五层，别再加：

| # | 层 | 内容 |
| --- | --- | --- |
| 8 | `Terrain` | 地面、山体、树、可破坏的栅栏 |
| 9 | `Player` | 玩家 `CharacterController`、玩家 HitBox |
| 10 | `Yao` | 妖的 `NavMeshAgent`、妖 HitBox |
| 11 | `Projectile` | 箭、泥丸、飞抓绳索 |
| 12 | `Interactable` | 采集点、喂养点、阵旗、掉落物（Trigger） |

矩阵（✔ = 互相碰撞/触发）：

|  | Terrain | Player | Yao | Projectile | Interactable |
| --- | --- | --- | --- | --- | --- |
| **Terrain** | ✔ | ✔ | ✔ | ✔ | ✘ |
| **Player** | ✔ | ✘ | ✔ | ✘（判定在 `Projectile` 侧做 Raycast，避免自伤） | ✔ |
| **Yao** | ✔ | ✔ | ✔（妖之间要挤开，否则围攻叠模） | ✔（被箭命中） | ✔ |
| **Projectile** | ✔ | ✘ | ✔ | ✘ | ✔ |
| **Interactable** | ✘ | ✔ | ✔ | ✔ | ✘ |

要点：
- `Projectile` 对 `Player` 关闭碰撞，用 `LayerMask` 在 `Projectile` 的 SphereCast 里排除 `Player`，
  这样「射击自己脚边的妖」不会被自己的胶囊挡住——这是解析式弹道最常见的翻车点。
- 妖与妖之间**必须**开碰撞：穷奇「优先咬信赖最低的妖」与多妖同场都依赖站位，叠模会让 W1/W2 全废。
- `Interactable` 全部是 Trigger，用 `QueryTriggerInteraction.Collide` 显式查询。

## 5. 弹道怎么实现：解析式 vs 刚体

| 维度 | 解析式（推荐） | 刚体（Rigidbody + gravity） |
| --- | --- | --- |
| 与 `Ballistics.cs` 一致性 | **完全一致**：落点 = `Drop(d, v)`，准星抬多少就是多少 | 不一致：`FixedUpdate` 积分误差随帧率漂移，准星要对刚体反推 |
| 可复算性 | 可以：同一组 (距离, 初速) 永远同一落点，便于 §7.3 验收 | 不行：`Time.fixedDeltaTime` 一改，表格数字全变 |
| 提前量 | 直接 `Lead(speed, d, v)`，准星自动张开 | 要单独再算一次，且与真实飞行不完全吻合 |
| 物理交互 | 无：箭不会弹跳、不会滚、不会被风吹偏 | 有：可弹跳、可堆积、可被风力影响 |
| 性能 | 每发一个 `Transform` 位移，零物理开销 | 每发一个刚体，100 发以上就会进 `Physics` 峰值 |
| 实现成本 | 30 行 `Projectile.Update` | 还要处理隧穿、`Continuous` 模式、休眠 |
| 权威性问题 | **落点由数学决定**，网络/回放一致 | 落点由物理引擎决定，跨平台可能微差 |

**推荐：全解析式。** 唯一例外是「流星锤」这类软器械（主方案 §6.2 给的是 1.5 m 绕行半径、
不是弹道），它也不需要刚体——用 `Spline` 或两段 Bezier 即可。

```csharp
// Projectile.Update —— 全文就这么点，公式全部来自 Ballistics
float t = Time.time - _launchTime;
if (t > _maxLife) { _pool.Release(this); return; }
float travelled = _speed * t;
transform.position = _origin + _dir * travelled + Vector3.down * (float)Ballistics.Drop(travelled, _speed);
```

命中检测用**线段扫掠**而不是每帧点检测：`Physics.SphereCast(prevPos, 0.05f, pos - prevPos, out hit, dist, mask)`。
高速箭（55 m/s × 1/60 s ≈ 0.92 m/帧）用点检测必然穿模，这是第二常见的翻车点。

## 6. 状态机：收刀 / 持械 / 蓄力 / 立契 / 倒地

状态与迁移条件表（`PlayerStateMachine`；`Trigger` 列即代码里的 `StateEvent`）：

| 当前状态 | 事件 | 条件 | 目标状态 | 副作用（谁执行） |
| --- | --- | --- | --- | --- |
| 收刀 Sheathed | `SheatheToggle` | 无（必成） | 持械 Armed | 兵器 `Socket_Back → Socket_Weapon`；`Agitation +25`（举兵器）；`Q_gear` 由 1 → 0 |
| 持械 Armed | `SheatheToggle` | 无（必成） | 收刀 Sheathed | 兵器换回背挂点；`Q_gear` 由 0 → 1 |
| 收刀 Sheathed | `Attack` | 手上是射器 | 蓄力 Charging | 进入蓄力计时 `t=0` |
| 持械 Armed | `Attack` | 近战 | 攻击 Attacking | 播一次挥击；`CombatProbe` 出判定 |
| 蓄力 Charging | `tick` | `t ≥ 1.25` | 蓄力 Charging（过拉） | 散布 ×`Ballistics.SpreadMultiplier(t)`，准星张开 |
| 蓄力 Charging | `tick` | `t ≥ 2.0` | 收刀 Sheathed | 强制脱手，体力 −15 |
| 蓄力 Charging | `Attack`（松开） | `0 < t < 2.0` | 收刀 Sheathed | 发射；伤害系数 = `ChargeDamageCoef(spec, t)` |
| 任意 | `Interact`（长按 0.8 s，§11.5） | 面前是妖且 `FirstFailingGate == 0` | 立契 Contracting | 播「把吃的放地上」；期间锁移动；短按只做普通交互，进不了立契 |
| 立契 Contracting | `ContractResolved` | — | 收刀 / 倒地 / 逃走 | 见下 |
| 任意 | `HpZero` | HP ≤ 0 | 倒地 Downed | HP 归零统一走这里，**不允许**别的脚本直接改状态 |
| 倒地 Downed | `GetUp` | 有妖且 `Trust ≥ 60`（护主）或 3 s 后 | 收刀 Sheathed | 护主：`Trust +8`（§5.1 唯一一次「玩家被击倒后它来挡」） |
| 倒地 Downed | `BacklashC1` | `BacklashResult.Consequence == C1` | 倒地（延长 2 s） | 伤害已由 `Backlash` 算好（`CPT_yao × 3.5`），这里只扣血 |

立契分支（`ContractDirector` 内部，不进玩家状态机）：

| 情况 | 结果 |
| --- | --- |
| `R < 1.00` | `BacklashOnSigning = 1.0` → 必触发 C1（红键，按下去 = 当场被咬） |
| `1.00 ≤ R < 1.25` | 掷**危险档曲线** `Contract.BacklashOnSigning(R)`（K3 默认 45%，档内递减 5 个点到 40%）→ 反噬；否则立契成功但进 7 日记仇期 |
| `R ≥ 1.25` | 只判定 `P_force` 成功/失败，**不会反噬** |
| `VolGates` 任一不满足 | 立契键灰显 + `Contract.GateHint` 原文提示，**不进入概率计算** |

> 状态机只做迁移，**不持有任何概率**。所有概率来自 `Stats`，随机数由调用方注入
> （`roll01`），这样 §4.4「R 从 1.24 跨到 1.26 必须跳档」才能在回放里复现。

## 8. 性能与美术降级建议（原型阶段）

主方案 §1.2 定的是 PC（Steam / itch.io），Steam Deck 可玩。原型目标：

| 指标 | 原型目标 | 说明 |
| --- | --- | --- |
| 帧率 | 1080p / **60 fps**，Deck 720p 锁 40 fps | 近战手感对帧率敏感，低于 45 会毁掉「攻速 0.75 vs 2.1」的差异感知 |
| Draw Call | **≤ 150** | 18 件兵器 + 14 种妖的切片只用 2 兵器 / 3 妖，150 很宽 |
| 三角面 | 场景 ≤ 30 万，单个妖 ≤ 8 千 | 妖是主角，钱花在妖身上 |
| 实时灯 | **≤ 2 盏**（1 方向光 + 1 跟随点光） | 火符 / 火环阵用贴片 + 粒子，不用真实光源 |
| 材质变体 | 每类角色 1 个 `MaterialPropertyBlock` 调色 | 避免 18 件兵器各一个材质 |

**可以砍掉的（按砍的顺序）**：
1. 实时阴影 → 烘焙 + 角色脚下贴片（省 20–40% GPU，视觉损失最小）
2. 后处理（Bloom/Vignette）→ 只留一层调色 LUT
3. 骨骼密度：妖从 60 骨降到 35 骨，W1 三档姿态只需要耳/尾/羽三根可读骨
4. 破坏物（栏栅、骨墙）→ 换成整块显隐 + 粒子
5. 布料/毛发 → 全砍，尾巴用手 K 或逐帧位移
6. 动态植被 → 静态 mesh + billboard
7. 音效分层（脚步/呼吸/毛发）→ 单层

**绝不能砍的**：W1–W4 四条预警（§5.4，是「长期共处」唯一的可感知载体）、
收刀/持械的动画切换（§4.2 G2 / Q_gear 的输入来源）、准星三点张开（§7.3 可读性）。
